## 永久保存的產品契約

「永久保存」指成功保存的個人副本沒有自動到期日，直到本人刪除；不受原旅程後續修改、刪除或退出共用影響。不宣稱無期限的基礎設施可用性，也不把瀏覽器快取當作雲端保存。

- 保存旅程名稱、日期、每日景點與規劃文字的快照，以及當下有權存取的景點照片。
- 個人感想、本人確認的到訪和首次體驗維持可編輯；原行程快照維持封存時版本。
- 不將排入行程的景點自動標成去過。
- 不複製票券、支出、付款資料、旅伴帳號或非景點照片附件。
- 保存來源由後端查驗；客戶端不能提供任意 Storage 路徑、任意 UID 或任意來源 URL。
- 已成功建立的個人副本與原旅程權限分開。建立副本前及複製過程仍檢查來源權限；已失去來源權限時不能補抓尚未保存的照片。
- 舊回憶顯示「尚未永久保存」並提供主動保存入口。沒有原照片時如實顯示無法補存，不做假資料、不背景掃描搬遷、不保留舊來源照片的顯示 fallback。

評估過的方式：只保留來源連結無法滿足永久保存；只下載到裝置不符合跨裝置重溫；採用帳號專屬的雲端副本，並保留本人刪除能力。

## 保存流程

1. 首頁點「收進回憶」，顯示簡短確認面板與「行程和照片將另存為個人回憶」說明。
2. 主操作「收好這趟旅行」先完成個人封存，不要求感想或到訪確認。確認後提供「查看回憶」「補上足跡」。
3. 接續要求後端建立保存作業。畫面明確區分回憶文字已保存與照片副本進度；若作業尚未成功建立，顯示「尚未永久保存／開始保存」。不可把第二個請求未完成的狀態當成保存成功。
4. 後端接受作業後持久化來源快照及照片清單，背景工作處理複製；使用者離開頁面不影響已接受的作業。
5. 每張照片有獨立完成進度。失敗保留已完成副本，重試同一作業，不重複製造檔案。
6. 僅在所有列入保存的照片都驗證完成後，顯示「已永久保存」。零照片的旅程可在快照保存成功後完成。
7. 照片缺失或權限中途撤銷時，顯示已保存張數與未完成原因；保留可讀的文字及已合法完成保存的部分，不把缺失照片默默從總數排除。

固定文案：`回憶已收好`、`照片保存中（{saved}/{total}）`、`照片尚未全部保存`、`重試未完成照片`、`已永久保存`。

## 儲存與服務邊界

- `personalTravel/{uid}/memories/{roomId}`：個人回憶與到訪，沿用 revision，不把照片工作進度混入使用者內容 revision。
- `travelMemoryArchives/{uid}/{roomId}`：一份個人永久快照與保存工作狀態。分成 `summary`、`itinerary`、`photos`、`operation` 子節點；前端列表僅訂閱 summary，詳情按需載入 itinerary/photos。operation 僅伺服器可讀寫，其餘本人可讀、客戶端不可寫。
- `travelMemories/{uid}/{roomId}/{operationId}/{photoId}`：個人 Storage 物件，與現有 `rooms/` 刪除命名空間完全分離。
- 身分一律從 Google auth 取得，所有請求驗證 roomId、operationId、revision 與數量界線。
- 沿用既有 Firebase Admin、Functions、RTDB、Storage 套件與背景工作模式，不新增套件、工作流或通用任務框架。

保存作業具有 `queued / copying / partial / complete / deleting / deleted` 狀態、操作 ID、有限工作租約和逐項進度。worker 只能在操作 ID 和租約仍匹配、且未進入刪除狀態時發布結果。背景事件重送或重複按鈕不得產生第二份副本。

照片來源限定目前行程中的 placePhoto，實際物件必須位於對應 room/place 路徑，metadata 的 roomId/itemId、MIME 與大小均須吻合。沿用圖片 5 MiB 上限及 JPEG/PNG/WebP/GIF 白名單，來源異常需明確報錯。

複製固定來源 generation，目的地使用不存在才建立的前置條件；不繼承公開下載 token 或任意 custom metadata。副本 metadata 只寫本人 UID、操作 ID、照片 ID 與允許的 MIME，使用私人快取設定。副本由已登入本人透過 Storage SDK 取得 Blob，不建立公開或長效簽名連結。

## 個人刪除與失敗清理

新增「刪除這份個人回憶」確認，明示會移除自己的文字、到訪及保存照片，不影響原旅程或旅伴。

- 刪除狀態先關閉保存工作發布權限，防止晚到回應復活資料。
- 清理範圍只能是該 UID／roomId／operationId 的前綴；不能清理 `rooms/` 或其他人的資料。
- 清除個人到訪時，相關收藏項目保留為「下次想去」，不保留失效 visited 關聯，護照章重算。
- Storage 刪除失敗則保留可重試的刪除狀態；完成前不顯示「已刪除」。只保留防止舊工作復活所需的最小 tombstone，不保留照片或私人感想。
- 延遲完成的 Storage 物件由 finalize 處理器依操作 ID／刪除狀態檢查清除；刪除使用物件 generation，防止舊事件刪除新副本。
- 對本次失敗產生的未引用物件提供可重試清理，不能只依賴瀏覽器 finally。

## 閱讀與操作設計

沿用現有 Button、ResponsiveBottomSheet、ConfirmDialog 與主題色。以照片、日期和一句感想為閱讀主體，主操作每頁只有一個，44px 以上觸控區域，手機以單欄呈現。

### 回憶詳情

卡片主操作改為「重溫這趟旅行」，詳情先顯示個人照片、感想與按天排列的保存行程；景點明確標記「已確認去過／尚未確認」。編輯、還原、複製和刪除放次要操作。讀取已保存回憶不訂閱原房間；「開啟原行程」保留獨立入口並依原權限控制。

已保存快照可用於複製新旅程，即使原旅程已刪除；複製只帶規劃資料，不帶個人照片、支出或到訪狀態。缺少永久快照時先引導完成保存。

### 草稿與衝突

回憶、收藏、複製表單按帳號與紀錄 ID 保存本機草稿及 base revision；成功保存才清除該草稿。關閉、背景點擊、Escape、返回和重新整理都有一致保護。切換帳號立即清除畫面中的上一帳號內容，不能自動套用到新帳號。

本機儲存不可用時明確顯示未備份；仍保留目前畫面輸入並阻擋無提示離開。不得把記憶體狀態稱為已保存草稿。

多端衝突時提供最新版本與本機草稿差異：未在遠端改動的欄位可保留本機值，雙方都修改的欄位由使用者選擇；不可只提升 revision 後覆蓋遠端，也不可要求關閉重開而丟失草稿。

### 到訪與城市

按天展開景點，支援選取多個地點後指定狀態及共同城市，顯示確認／未確認數量。儲存區固定在面板底部，欄位錯誤定位到第一個缺少城市的已到訪地點。

城市選擇沿用既有 Places 搜尋能力，但需取城市識別、國家、顯示名稱與座標；可從本人已使用的城市選擇，不由單一旅程目的地自動推定跨城市行程。資料以城市識別分組，同名異國不合併。既有自由文字保留為待整理項，提供本人明確指定同一城市的操作，不猜測合併、不背景搬遷。

臨時到訪可新增到個人回憶，明確標示為本人補登，與原行程來源項分開驗證；不修改旅伴的行程。

### 收藏、首次體驗、分享和導覽

- 收藏城市先選「建立再訪清單」或「加入既有主題」。再訪目的地初始為想去，不因歷史到訪立即完成；可挑選項目並避免重複加入同一來源。
- 留待下次可加入既有收藏，不再每次建立新清單。尚未加入的有效地點在儲存收藏時一併處理，無效項目就地提示。
- 同一帳號每種首次體驗只指定一趟旅程；已有來源時顯示目前旅程，改指定需要明確操作。重遊章開啟城市跨年紀錄，收藏章開啟其收藏，不任意跳到一筆編輯表單。
- 搜尋涵蓋景點感想。年度回顧可呈現本人選定的代表照片與感想，不增加排行或花費門檻。
- 分享預設不勾個人感想；可選日期、城市和感想，先預覽再分享，支援原生文字分享與複製；本次不提供公開照片網址。
- 頁籤、選定回憶／城市、年份與搜尋條件反映在 URL；重新整理、上一頁可回到相同內容。帳號切換後不顯示前帳號資料。
- 複製新旅程按原天數推算回程日期，允許本人調整並即時顯示限制；完成後直接提供開啟新旅程。

## 驗收情境

1. 7 天、40 個景點、3 座城市、12 張照片：不填遊記即可封存，照片有進度，之後可補足跡。
2. 保存完成後刪除原旅程及撤銷原權限：重新登入仍看得到自己的快照與照片，其他帳號全部讀取失敗。
3. 第 5 張複製失敗、關閉頁面、重試：前 4 張不重複複製，完成後總數為 12，失敗時不能顯示全部完成。
4. 保存途中來源撤銷、來源檔案更換 generation：不補抓無權限或不一致的檔案，顯示未完成原因。
5. 保存與個人刪除同時發生、延遲 finalize 重送：刪除後無資料復活、無殘留個人照片、原旅程與其他人副本不變。
6. 同一頁草稿關閉重開、斷線重整、帳號切換、本機儲存失敗、兩裝置同時修改：輸入不靜默遺失、不跨帳號、不覆蓋遠端。
7. 京都不同文字但相同城市識別合併；同名不同國家不合併；批次城市選擇不自動宣稱到訪。
8. 再訪清單初始未完成；加入既有收藏不重複；首次體驗只有一個來源；護照章連到正確閱讀畫面。
9. 手機 390×844、桌機、200% 字級、鍵盤操作：主操作可達、錯誤可定位、對話框焦點正確、無水平溢位。
