# Release 2026.07 — 行程規劃、地圖與記帳全面升級

- Release version: `2026.07-trip-management-redesign`
- Published at: `2026-07-30`
- Release branch: `release/editable-demo-sandbox-rc`
- Release PR: #38 (Draft，等待人工 Gate 3 審核)
- Source of truth: `src/config/releaseNotes.js`

本文件描述這個 release 對使用者的實際改變、資料安全邊界、已知限制與回滾方式。這是 Release Candidate 文件；Gate 3 尚未批准，也尚未部署到正式環境。

## 使用者可見範圍

這個版本重整旅程管理的主要介面，並讓「更新內容」、「功能介紹」與「功能導覽」與實際畫面一致：

1. 手機與桌面規劃介面重整。
2. 地圖與行程保持同步。
3. 記錄旅伴是否已完成轉帳。
4. 景點資料集中管理。
5. 外觀與旅程工具整合。
6. 可編輯範例旅程與新版指引。

不包含新的收費功能、帳號機制、通知機制或第三方整合。

## 本機可編輯範例旅程

- 未建立任何旅程時，Lobby 顯示可開啟的範例旅程入口。
- 範例旅程可直接編輯，重新整理後仍保留內容。
- 範例只保存在本機瀏覽器，不會寫入正式雲端旅程，也不會出現在 `myTrips`。
- 範例不使用雲端同步，因此不顯示同步狀態，且雲端限定功能會明確說明無法使用。
- 使用者可以用明確的重設操作清除本機範例內容。
- 「功能介紹」共五步，首次使用會自動顯示，之後可從 Lobby 或設定重新播放。重新播放不會改變 onboarding 狀態。

## 響應式行程規劃

- 手機使用單日時間軸：以天數切換選擇日期，時間軸依順序顯示當天景點。
- 桌面保留多日並排規劃：每天一張可命名主題的規劃卡，可在同一畫面比較與調整多天行程。
- 低頻操作不再散落在卡片上，而是集中到景點資訊。
- 桌面景點卡只保留一個明確的「景點資訊」動作，不再顯示手機版的「⋯」選單。
- 手機景點卡保留導航與「⋯」操作選單。

## 地圖體驗

- 地圖依當日順序顯示標記與路線。
- 地圖景點卡、選取狀態與天數切換互相同步。
- 手機透過底部「地圖」分頁進入；桌面地圖與行程並排顯示。
- 缺少座標的景點不會中斷地圖顯示，會以明確狀態呈現。

## 結算與轉帳紀錄

- 記帳分頁可記錄共同支出與分攤方式。
- 結算建議可標記「已轉帳」，也可取消標記。
- 轉帳狀態會保存，重新整理後仍保留。
- 金額計算維持守恆，不用浮點近似掩蓋差異。

## 外觀與設定

- 外觀設定改為明確介面，不再依賴隱藏的顏色輸入互動。
- 分享共編、共享清單與匯出集中到設定。
- 設定維持單一結構，行動版為 bottom sheet、桌面版為選單，兩者共用同一份內容。
- 設定項目：旅程工具、外觀設定、更新內容、功能介紹、功能導覽、檢查更新、安裝狀態、版本資訊。
- 版本資訊卡顯示 `2026.07-trip-management-redesign`。

## 協作與同步

- 正式旅程支援多人即時同步：景點、行程排序、費用、票券與清單會在其他裝置更新。
- 旅程頁顯示連線、同步中、已同步與遠端更新狀態。
- 範例旅程不參與同步，因此不顯示同步狀態。
- 「功能導覽」會依當前裝置與畫面解析目標；目標不在畫面上時改用說明式步驟，不會替使用者切換分頁，也不會聚焦被隱藏的元素。

## 資料安全

- 沒有資料 migration。
- 沒有修改 Firebase Security Rules。
- 沒有修改 Firebase 或建置設定。
- 沒有新增、移除或升級任何套件；`package.json` 與 `package-lock.json` 未變更。
- 範例旅程不寫入 Firebase、不寫入 `myTrips`、不寫入 Offline Trip Cache。
- 測試只使用 Firebase Emulator 專案 `demo-travel-e2e`，沒有存取正式 Firebase。
- 舊版本的 release seen key 不會被刪除；新版本使用自己的 key，因此使用者會看到一次新的「更新內容」。
- PWA 更新仍為使用者觸發：偵測到新版本時顯示提示，由使用者決定何時重新載入，不會自動強制更新或清除資料。

## 已知限制

- 真實路線與行車時間需要有效的 Google Maps 設定；未設定或額度受限時，地圖與路線會以降級狀態顯示，而不是保證顯示真實路線。
- 景點缺少座標時會以降級方式處理：仍可保留在行程與清單中，但不會出現在地圖標記或路線計算。
- 離線行為不是完整離線編輯。最近開啟的旅程提供唯讀離線預覽；離線期間不保證可編輯或同步。
- iPhone 拖曳排序為已驗證可接受的行為，但不宣稱在所有 iOS 版本、瀏覽器與手勢下都完美無誤。
- 「功能導覽」一次只聚焦第一個符合條件且可見的目標；重複元素不會全部標示。
- Release seen 狀態儲存在各裝置的 localStorage，不跨裝置同步。

## 回滾方式

### Git revert

RC 尚未合併，最安全的回滾是不合併 PR #38。若已合併到 `main`：

```bash
git revert -m 1 <merge-commit-sha>
```

此 release 只變更前端內容、元件與測試，沒有 migration 或 Rules 變更，因此 revert 不需要資料修復步驟。使用者本機的 release seen key 會殘留，但不影響功能：回到舊版本後會使用舊 key，不會遺失資料。

### Vercel rollback

在 Vercel 專案的 Deployments 中選擇前一個成功的 Production deployment，執行 Promote/Rollback 即可還原前端。因為沒有 API、schema 或 Rules 變更，前端 rollback 不需要搭配後端調整。

## 部署後 smoke checklist

在正式環境完成部署後，以手機與桌面各檢查一次：

1. 開啟 App，確認「更新內容」顯示 `2026.07-trip-management-redesign`、標題「行程規劃、地圖與記帳全面升級」與六個項目。
2. 「稍後再看」與「不再顯示此版本」都能關閉，且「不再顯示此版本」在重新載入後不再自動彈出。
3. 從設定開啟「功能介紹」，確認五步都可前進、返回並關閉；320px 寬度沒有水平溢出。
4. 從設定開啟「功能導覽」，確認手機與桌面各步驟聚焦到實際可見元素，沒有聚焦空白區域，且導覽不會自行切換分頁。
5. 手機：以單日時間軸切換天數、開啟景點資訊、確認導航與「⋯」操作可用。
6. 桌面：確認多日並排規劃、日主題命名與卡片上的「景點資訊」可用。
7. 地圖：確認標記與路線依當日順序顯示，選取景點時與行程同步。
8. 記帳：新增一筆共同支出，在結算建議標記「已轉帳」，重新整理後確認狀態保留，再取消標記。
9. 票券：確認票券與附件可保存與開啟。
10. 設定：確認更新內容、功能介紹、功能導覽、檢查更新、安裝狀態與版本資訊都存在且沒有重複項目。
11. 範例旅程：開啟、編輯、重新整理確認保留，並確認它沒有出現在正式旅程清單中。
12. 協作：以兩個裝置或兩個瀏覽器確認景點與費用會即時更新，且同步狀態指示正確。
