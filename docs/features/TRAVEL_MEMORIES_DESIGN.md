# 旅行回憶、我的足跡與收藏

三批功能及 2026-10-17 永久保存優化延續同一 Draft PR，由人工合併。完整生命週期與驗收契約見[永久保存設計](../superpowers/specs/2026-10-17-memory-permanent-save-design.md)。

## 產品與資料界線

- 首頁列出尚未個人封存的旅行。結束日期過後提示「完成並收進回憶」；不會因日期自動判定到訪或自動封存。
- `personalTravel/{uid}` 是帳號專屬資料，與 `rooms`、`roomAccess`、`userTrips` 分開。新增模型為本次功能所需，不修改既有旅程或權限模型。
- `memories/{roomId}` 保存 archived、archivedAt、revision、旅程標題/日期摘要、個人感想、到訪確認與首次體驗。還原只清除 archived，保留已確認的到訪。
- 到訪按行程景點穩定 ID 記錄，狀態為 visited / missed / wishlist；未確認不產生足跡。每筆保存名稱、本人確認的城市、座標、日期、感想；城市不可從目的地自動推定。
- 城市以明確選擇的 Places 城市 ID 分組，保存國家、名稱、城市座標；搜尋限定城市。舊文字紀錄列為待整理，不猜測合併，也不增加已識別城市數。支援按天批次指定及本人補登，無須 GPS。
- 「收好這趟旅行」先封存，再建立獨立的行程／景點照片保存作業。成功的個人副本沒有自動到期日，直到本人刪除；來源修改、退出共用或原旅程刪除不影響副本。尚未保存、進行中、部分失敗與完成分開顯示。舊回憶由本人主動保存，沒有來源照片顯示 fallback。
- 卡片先開啟唯讀故事、每日行程原文、照片及到訪狀態；另有編輯、還原、複製及個人刪除。複製由後端讀取本人已保存快照，照片部分失敗也可複製規劃；不帶金額、付款、待辦完成、票券、個人照片或來源 Storage 路徑。
- 收藏是本人建立的主題清單，每項有名稱、城市、wishlist/visited 與可選的回憶關聯。到訪項目必須對應本人確認的 visited 地點，避免規劃清單直接成為成就。
- 城市再訪清單從想去開始，可加入既有收藏並依來源去重；有效的待加入文字會隨儲存一併加入。首次體驗每種只指定一趟旅行，改指定須本人明確選擇。重遊章連至城市歷年紀錄，收藏章連至該清單。
- 年度回顧可選代表回憶及照片；頁籤、回憶、城市、年份、照片與搜尋條件保留在 URL。分享可選日期、城市、感想並預覽；感想預設關閉，支援原生文字分享／複製，不產生公開照片或資料節點。

## 持久化與安全

採 Google 身分的 callable 寫入，所有 UID 從 auth 取得，不接受呼叫者指定擁有者。資料以帳號交易與 revision 防止多端覆寫。新增 owner-only RTDB 讀取規則以提供即時帳號同步，客戶端直接寫入維持禁止。使用者已明確授權本次新增模型與節點規則；現有共享旅程規則不變。

私人節點：

- `personalTravel/{uid}`：本人 Google 帳號讀取；client write 禁止。
- `travelMemoryArchives/{uid}/{roomId}/summary|itinerary|photos`：本人 Google 帳號讀取；`operation` 僅伺服器可讀寫。
- `travelMemories/{uid}/{roomId}/{operationId}/{photoId}`：本人 Google 帳號透過 Storage SDK 讀取 Blob；無下載 token，client write 禁止。

後端限定目前有權讀取的景點照片，檢查路徑、metadata、MIME、大小及固定 generation。分批 worker 保留進度、租約與清理意圖；重送不重複複製。本人刪除先寫防復活標記，再清除該命名空間；失敗自動重試，延遲 finalize 以 generation 清理，不碰來源或其他帳號。

所有資料以帳號及 listener 世代隔離；換帳號立即隱藏前帳號內容，晚到請求不能回填。表單保存本機草稿與原始 revision，離線可編輯、不可送出。關閉、Escape、返回與重新整理保護輸入；本機儲存失敗會明確提示。多端更新使用原始／本機／最新內容比較，衝突欄位須本人選擇，不能只提高 revision 覆蓋。

## 三批驗收

1. 雙使用者共同旅程只有執行者首頁移除；另一位權限/首頁不變。重載後封存仍在；回憶可搜尋、按年份呈現、還原與複製。
2. 可略過到訪確認；之後可補、可更正。只有 visited 進足跡，同城兩趟顯示兩次。地圖及城市列表連回旅程、感想、受保護照片。
3. 自訂主題清單可新增/編輯/刪除項目、顯示進度與下次想去。首次體驗須本人確認；收藏/重遊章有來源。年度可切換，分享須先勾選內容。

## 驗證與交付

沿用既有 Vitest、Node test、Playwright 和 Firebase Emulator。新增後端授權/驗證/衝突測試、前端計算與互動測試、跨頁與雙帳號 E2E。執行 verify:fast、相關 E2E、git diff --check；不部署、不修改套件鎖檔或 CI。三輪修補仍失敗須記錄並停止擴大修改。
